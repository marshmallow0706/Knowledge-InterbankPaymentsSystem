## 9.1 構成要素

```mermaid
flowchart TB
  subgraph 金融機関A
    KA[勘定系システム] --- RCA[RC<br/>中継コンピュータ]
  end
  subgraph 金融機関B
    KB[勘定系システム] --- RCB[RC]
  end
  subgraph 共同センター
    KC[共同利用型勘定系<br/>信金・地銀等] --- RCC[RC]
  end
  subgraph 全銀センター（東京・大阪の2拠点）
    CORE[コアタイムシステム]
    MORE[モアタイムシステム]
  end
  RCA <== 多重化回線 ==> CORE & MORE
  RCB <== 多重化回線 ==> CORE & MORE
  RCC <== 多重化回線 ==> CORE & MORE
  CORE <--> BOJNET[(日銀ネット)]
  MORE <--> BOJNET
```

| 要素 | 役割 |
|---|---|
| **全銀センター** | 為替通知の受信・検証・中継、決済額の計算、日銀ネットへの決済データ送信 |
| コアタイムシステム | 平日日中の処理 |
| モアタイムシステム | 平日夜間・休日の処理（2018年〜） |
| **RC（Relay Computer：中継コンピュータ）** | 各金融機関（または共同センター）に設置。勘定系の送金依頼を全銀システムの電文形式に変換し、センターとの通信を担う。障害時にも取引を継続するための機能を持つ |
| 勘定系システム | 各金融機関の預金元帳。入出金を記帳する |
| 日銀ネット | 日本銀行の金融ネットワークシステム。大口 RTGS と小口の差額決済を実行 |

RC の詳細は[仕組み編 第2章](../mechanism/02_relay_computer_and_network.md)を参照。

## 9.2 可用性・事業継続

| 対策 | 内容 |
|---|---|
| 2センター体制 | 全銀センターを **東京・大阪の2か所** に設置 |
| 回線の多重化 | センターと各金融機関を結ぶ回線を多重化 |
| 機器の冗長化 | センター・RC の主要機器を冗長構成 |
| バックアップ運用 | 障害時の代替手段（例：ファイル連携による代替送信）を規則で整備 |
| 訓練 | 加盟銀行を交えた障害対応・BCP 訓練 |

2023年10月の障害は、センターではなく **一部の金融機関の RC** で発生し、その金融機関の為替取引が全面的に不能になりました。
冗長化されていても同じソフトウェアの不具合は両系で発生しうる、という教訓を残しました（→[仕組み編 第9章](../mechanism/09_incidents_and_bcp.md)）。

## 9.3 更改サイクル（レベルアップ）

全銀システムは概ね **8年ごと** に機器・ソフトウェアを一新しており、全銀ネットはこれを「レベルアップ」と呼んでいます（周期は減価償却サイクルにおおよそ沿う）。

| 世代 | 稼働 | 主なトピック |
|---|---|---|
| 第1次 | 1973年 | 全銀システム稼働、即時入金を実現 |
| 第2次〜第5次 | 1979年〜2003年 | 処理能力の増強、接続方式の高度化 |
| 第6次 | 2011年 | 大口取引の日銀ネット RTGS 決済 |
| 第7次 | 2019年 | 24時間365日化（モアタイム、2018年先行稼働）への対応 |
| 第8次 | 2027年（予定） | RC の更改から段階的に移行（2023年に最初の RC 入替で障害） |

- 1,000を超える金融機関が同時に接続しているため、全機器を一斉に入れ替えるのではなく、各金融機関の RC の保守期限等に合わせて **順次入れ替え**、新旧が混在する期間があります
- 各世代の正確な稼働年月は全銀ネットの公表資料を参照してください

## 9.4 セキュリティ

公開情報の範囲での整理です（具体的な実装は非公開）。

| 観点 | 内容 |
|---|---|
| ネットワーク | インターネットから分離された専用ネットワーク |
| 接続認証 | 接続できるのは全銀ネットの試験を経た加盟銀行の RC のみ |
| 電文の完全性 | 電文の改ざん・なりすまし・二重送信を防ぐ仕組み |
| 運用 | 開発・運用ベンダーへの委託管理、変更管理、試験体制 |

模擬システムでは、これらを学ぶために次を実装しています。

| 脅威 | 模擬の対策 | 応答コード |
|---|---|---|
| 改ざん | HMAC-SHA256 による MAC 検証 | E03 |
| なりすまし | 電文の仕向銀行コードと送信元（鍵）の一致確認 | E04 |
| 二重送信・再送攻撃 | 仕向銀行＋通番の重複チェック | E05 |
| 不正な宛先 | 被仕向金融機関コードの登録確認 | E06 |
